Het oefenvoorbeeld

Door de hele handleiding loopt één klein voorbeeld: een kantoorgebouw met drie verdiepingen, zes ruimten en acht bouwelementen (wanden, deuren, radiatoren en een luchtbehandelingskast). Elk element is op twee manieren ingedeeld: met een elementcode en met een onderhoudsindeling. Beide indelingen wijzen naar dezelfde elementen.

Alle namen en codes zijn verzonnen oefendata. Het zijn geen echte classificatietabellen; de codes lijken expres niet op een bestaand stelsel.

De oefendata zit in de skill neo4j-starter als het bestand voorbeelddata.zip: download de skill op knowledge.bimforce.com/skills, pak hem uit en je vindt de zip in de map neo4j-starter. Pak die ook uit; je krijgt een map voorbeelddata met vier CSV-bestanden (verdiepingen.csv, ruimten.csv, klassen.csv, elementen.csv) en één script, laden.cypher, dat dezelfde graph opbouwt zonder CSV. Beide routes leveren 27 nodes en 40 relationships op. Het script staat ook onderaan hoofdstuk 4, om te kopiëren.

1

Wat een graph database is en wanneer hij past

Een graph database bewaart gegevens als dingen en de verbanden ertussen. Een ding heet een node (een knooppunt, zoals één ruimte of één radiator). Een verband heet een relationship (een benoemde pijl tussen twee nodes, zoals STAAT_IN). Elke node krijgt een label (de soort: Ruimte, Element) en eigenschappen, properties genoemd (naam-waardeparen zoals oppervlakte: 145). Ook een relationship kan properties hebben. Je vraagt de gegevens op met Cypher, de querytaal van Neo4j, die een verband opschrijft als een tekening: (radiator)-[:STAAT_IN]->(ruimte).

Het verschil met Excel en met een relationele database zit in waar de verbanden leven.

ExcelRelationele databaseGraph database
VormTabbladen met rijenTabellen met vaste kolommenNodes en relationships
VerbandenEen code in een kolom, opzoeken met VERT.ZOEKENSleutels, samengevoegd met een JOIN tijdens de vraagOpgeslagen als relationship; je loopt erlangs
Sterk inRekenen, lijsten, snel iets bijhoudenVeel gelijksoortige records, transacties, rapportagesVerbanden over meerdere stappen, indelingen naast elkaar, een structuur die nog groeit
Minder sterk inMeerdere gebruikers, verbanden over meer dan twee lijstenEen schema dat vaak verandert, vragen over veel tussenstappenGrote berekeningen over kolommen, financiële administratie

Wanneer hij past

  • Je vragen gaan over verbanden: welk element zit in welke ruimte, valt onder welke klasse, hoort bij welk onderhoudscontract.
  • Hetzelfde ding zit in meer dan één indeling, en je wilt niet kiezen welke de "echte" is.
  • De structuur verandert nog. Een nieuw soort verband toevoegen kost geen herbouw van tabellen.
  • Je wilt laten zien hoe iets samenhangt. De graphweergave is direct bespreekbaar met collega's.

Wanneer niet

  • Je hebt vooral één lange lijst met kolommen en wilt sommen, filters en grafieken. Dan is Excel of een relationele database eenvoudiger.
  • Het gaat om boekhouding of transacties met strenge vaste formulieren. Daar zijn relationele databases voor gemaakt.
  • Niemand gaat de graph onderhouden. Een graph met verouderde verbanden misleidt meer dan een verouderde lijst.

Meer achtergrond: What is a graph database? in de documentatie van Neo4j (Engels).

2

Neo4j Desktop installeren en je eerste database maken

Neo4j Desktop is een gratis programma voor Windows, macOS en Linux waarmee je Neo4j op je eigen computer draait. Deze handleiding gaat uit van Neo4j Desktop 2. Versie 1 ziet er anders uit; oudere uitleg en video's met knoppen als "Add Graph" horen daarbij.

Namen van knoppen en menu's komen uit de documentatie van Neo4j Desktop (Engels). In jouw versie kunnen ze iets anders heten of op een andere plek staan.

Installeren

  1. Ga naar het Deployment Center van Neo4j en download Neo4j Desktop voor jouw computer.
  2. Windows: dubbelklik op het gedownloade installatiebestand en volg de stappen. Mac: open het .dmg-bestand in Downloads en sleep Neo4j Desktop naar de map Programma's.
  3. Start Neo4j Desktop. Volgens de installatie-uitleg heb je Windows 10 met PowerShell 5.1 of hoger nodig, of macOS 10.10 of hoger.

Je eerste instance maken

Een instance is één Neo4j-server op je computer. Een instance bevat altijd twee databases: system (voor de server zelf) en neo4j (de jouwe). In neo4j zet je de oefendata.

  1. Klik bij de eerste keer openen op Get started. Werk je al in een project, gebruik dan de knop Create instance.
  2. Geef de instance een naam, bijvoorbeeld Oefenkantoor.
  3. Laat de Neo4j-versie op de standaard staan: de nieuwste. Kies je een andere versie, dan moet Desktop die eerst downloaden.
  4. Vul een gebruikersnaam en een wachtwoord in. Die gelden voor alle databases in deze instance. Bewaar ze in je wachtwoordbeheerder en gebruik geen wachtwoord dat je ook ergens anders gebruikt.
  5. Bevestig. De instance verschijnt in de lijst met het etiket New, tot je hem voor het eerst start.

Starten en stoppen

  • Start de instance met de startknop op de kaart. Stoppen doe je met dezelfde knop, opnieuw starten met de herstartknop.
  • Er kan in Neo4j Desktop maar één instance tegelijk draaien. Start je een andere, stop dan eerst de lopende.
  • Sommige handelingen, zoals een back-up maken, kunnen alleen bij een gestopte instance (hoofdstuk 7).

Waar de bestanden staan

Neo4j Desktop zet alles in een verborgen map in je gebruikersmap. Volgens de installatie-uitleg:

  • Windows: %USERPROFILE%\.Neo4jDesktop2\. Elke instance krijgt daarbinnen een eigen map onder Data\dbmss\.
  • Mac: ~/Library/Application Support/neo4j-desktop/Application/

Je hoeft die mappen niet zelf te zoeken. Kies in het menu met drie puntjes van de instance Open > Instance folder. In die map staat onder meer de map import, die je in hoofdstuk 6 nodig hebt. Het pad staat ook op de kaart van de instance.

Gelukt? De instance Oefenkantoor draait en via Connect > Query opent de querytool.

Bronnen: Instance management en Visual tour (Engels).

3

De querytool en de graphweergave

De tool Query is waar je Cypher typt en de uitkomst bekijkt. Buiten Desktop heet dezelfde tool Neo4j Browser. Open hem via Connect > Query op de kaart van je instance, of via Query in de zijbalk en kies dan je instance en de database neo4j.

Zet eerst de oefendata erin. Kopieer het script laden.cypher onderaan hoofdstuk 4, plak het in de editor en voer het uit.

Een query draaien

Cypher
MATCH (n)-[r]->(m)
RETURN n, r, m
  1. Plak de query in de editor bovenaan.
  2. Klik op de afspeelknop. Onder de editor verschijnt een resultaatkader met de query en de uitkomst.
  3. Je kunt de query in het kader aanpassen en opnieuw uitvoeren. Eerdere queries vind je terug in History in de zijbalk; vaste queries bewaar je met Saved Cypher.

Het resultaat lezen

WeergaveWat je zietHandig voor
GraphNodes als bolletjes, relationships als pijlenZien hoe iets samenhangt, met collega's bespreken
TableElke rij van het resultaat, met de properties als tekstWaarden aflezen, tellingen, lijsten

De graphweergave verschijnt alleen als je nodes of relationships teruggeeft (zoals RETURN n, r, m). Vraag je alleen properties op (RETURN r.naam), dan krijg je een tabel.

Nodes aanklikken en uitklappen

  • Eén keer klikken op een node toont zijn label en properties in het overzicht naast de graph.
  • Dubbelklikken klapt de node uit: Neo4j haalt de nodes erbij die er direct aan vastzitten. Nog eens dubbelklikken maakt dat ongedaan.
  • Rechtsklikken geeft een menu met onder meer uitklappen, inklappen en de node uit beeld halen.

Kleuren en bijschriften per label

  1. Klik in het overzicht op een label, bijvoorbeeld Element.
  2. Kies een kleur, een grootte en het bijschrift (Caption): de property die op het bolletje staat. Kies voor Element de property naam en voor Klasse de property code.
  3. Voor relationship types werkt het net zo, met kleur, lijndikte en bijschrift.

Neo4j kiest zelf een bijschrift als je niets instelt. Heeft een node meer labels, dan bepaalt het eerste label in de lijst de opmaak. Bron: Query operations (Engels; de tool in Desktop is dezelfde als in Aura, op een paar onderdelen na).

Het schema bekijken

Wil je zien welke soorten nodes en relationships er zijn, zonder alle gegevens: vraag het schema op.

Cypher
CALL db.schema.visualization()

Je krijgt één bolletje per label en één pijl per soort verband: Gebouw, Verdieping, Ruimte, Element, Klasse en Stelsel, met de pijlen daartussen. Dat is je datamodel, afgeleid uit wat er werkelijk in de database staat. In de zijbalk toont Database information daarnaast het aantal nodes en relationships en alle labels, relationship types en property keys.

Gelukt? De eerste query toont 40 rijen in de tabel en een graph met 27 nodes. Het schema toont zes labels.

Bron: Query in Neo4j Desktop (Engels).

4

Cypher in tien stappen

Cypher beschrijft wat je zoekt als een tekening van haakjes en pijlen. Elke stap hieronder heeft één uitleg, één query en wat je terugkrijgt met de oefendata. Voer ze in volgorde uit: stap 3 tot en met 6 maken en verwijderen een extra element, zodat je aan het eind weer bij de oorspronkelijke 27 nodes uitkomt.

De queries zijn geschreven voor Neo4j 5 en nieuwer, en getoetst op een lege oefendatabase met de oefendata. Hoofdletters zijn voor Cypher-woorden niet nodig, maar maken een query leesbaar. Voor labels, relationship types en properties maken hoofdletters wel verschil: Ruimte is iets anders dan ruimte.

1 Het patroon: MATCH en RETURN

Met MATCH beschrijf je wat je zoekt, met RETURN wat je terug wilt zien.

Cypher
MATCH (e:Element)-[:STAAT_IN]->(r:Ruimte)
RETURN e.naam, r.naam

Je krijgt een tabel van 8 rijen: elk element met de naam van zijn ruimte, bijvoorbeeld Radiator kantoortuin 1e en Kantoortuin. Schrijf RETURN e, r in plaats van de properties, dan zie je hetzelfde als graph.

2 Filteren met WHERE

WHERE houdt alleen de treffers over die aan een voorwaarde voldoen.

Cypher
MATCH (r:Ruimte)
WHERE r.oppervlakte > 100
RETURN r.code, r.naam, r.oppervlakte
r.coder.naamr.oppervlakte
R1.01Kantoortuin145
R2.01Kantoortuin150

Andere voorwaarden: =, <> (niet gelijk), STARTS WITH 'R1', CONTAINS 'deur', IN ['wand', 'deur'], en combinaties met AND en OR.

3 Iets nieuws maken met CREATE

CREATE maakt altijd een nieuwe node of relationship, ook als er al precies zo een bestaat.

Cypher
CREATE (b:Element {id: 'E09', naam: 'Brandblusser entree', type: 'brandblusser'})
RETURN b

Je krijgt één nieuwe node. Voer je dezelfde query nog eens uit, dan weigert Neo4j: er bestaat al een Element met id E09. Dat komt door de unieke sleutel die laden.cypher heeft aangemaakt (hoofdstuk 5). Zonder die sleutel had je nu twee brandblussers met hetzelfde id gehad.

4 Zoeken of maken met MERGE

MERGE zoekt eerst het hele patroon en maakt het alleen als het er nog niet is. Daarom is MERGE meestal de betere keuze als je gegevens laadt of aanvult.

Cypher
MERGE (b:Element {id: 'E09'})
  ON CREATE SET b.naam = 'Brandblusser entree', b.type = 'brandblusser'
RETURN b

Je krijgt de bestaande brandblusser uit stap 3, zonder foutmelding en zonder dubbele. ON CREATE SET vult properties alleen in als de node nieuw is. Een relationship leg je zo, ook als hij er al ligt:

Cypher
MATCH (b:Element {id: 'E09'}), (r:Ruimte {code: 'R0.01'})
MERGE (b)-[:STAAT_IN]->(r)
RETURN b.naam, r.naam

Zet in MERGE alleen de sleutel. MERGE (b:Element {id: 'E09', naam: 'Blusser'}) zoekt een node met precies dat id én die naam. Heet hij anders, dan probeert MERGE een nieuwe te maken. Zoek op de sleutel en zet de rest met SET of ON CREATE SET.

5 Properties wijzigen met SET

SET geeft een property een waarde, of voegt hem toe als hij nog niet bestond.

Cypher
MATCH (b:Element {id: 'E09'})
SET b.installatiedatum = date('2024-05-01'), b.merk = 'onbekend'
RETURN b

Je krijgt de brandblusser met twee nieuwe properties. date('2024-05-01') slaat een echte datum op, geen tekst; daarmee kun je later rekenen en sorteren. Een property weghalen doe je met REMOVE b.merk.

6 Verwijderen met DELETE en DETACH DELETE

DELETE verwijdert een node zonder relationships; DETACH DELETE haalt eerst de relationships weg en daarna de node.

Cypher
MATCH (b:Element {id: 'E09'})
DETACH DELETE b

Je krijgt een melding dat er één node en één relationship zijn verwijderd. Probeer je het met alleen DELETE b, dan weigert Neo4j, omdat de brandblusser nog aan de entree vastzit.

Er is geen prullenbak. Wat je verwijdert is weg. Draai eerst de MATCH met RETURN in plaats van DELETE en kijk wat je raakt. MATCH (n) DETACH DELETE n zonder voorwaarde leegt de hele database. Maak vóór grote ingrepen een back-up (hoofdstuk 7).

7 Sorteren en beperken met ORDER BY en LIMIT

ORDER BY zet de rijen op volgorde, DESC van groot naar klein, LIMIT kapt af na een aantal rijen.

Cypher
MATCH (r:Ruimte)
RETURN r.naam, r.oppervlakte
ORDER BY r.oppervlakte DESC
LIMIT 3

8 Tellen en groeperen

count() telt, collect() maakt een lijst. Alles in RETURN dat geen telling is, wordt vanzelf de groepering.

9 Paden van variabele lengte

Met *1..2 in de relationship laat je Neo4j één tot twee stappen ver zoeken; met | sta je meer relationship types toe.

Cypher
MATCH (:Gebouw {code: 'KG'})-[:HEEFT_VERDIEPING|HEEFT_RUIMTE*1..2]->(r:Ruimte)
RETURN r.code, r.naam

Je krijgt alle zes ruimten van het gebouw, via de verdiepingen. Je hoeft niet te weten hoeveel lagen ertussen zitten. Wil je de weg zelf zien, geef het pad dan een naam:

Cypher
MATCH pad = (:Gebouw {code: 'KG'})-[*..3]-(:Element {id: 'E06'})
RETURN pad

Je krijgt één pad van drie stappen in de graphweergave: Oefenkantoor, Begane grond, Technische ruimte, Luchtbehandelingskast. Zonder pijlpunt in het patroon (-[*..3]-) maakt de richting niet uit. Houd de bovengrens klein: zonder grens zoekt Neo4j door de hele graph.

10 Parameters

Een parameter is een invulplek in een query, aangegeven met $, zodat je dezelfde query met een andere waarde kunt draaien zonder hem te herschrijven.

Cypher
:param ruimte => 'R1.02'
Cypher
MATCH (e:Element)-[:STAAT_IN]->(:Ruimte {code: $ruimte})
RETURN e.naam

Je krijgt Deur vergaderruimte en Radiator vergaderruimte. De eerste regel is een opdracht aan de querytool zelf, geen Cypher: hij zet de parameter. Zo werkt het in Neo4j Browser; in Query kun je de parameter ook instellen in de lade Parameters in de zijbalk. Parameters zijn ook de veilige manier om waarden vanuit een ander programma of een AI-assistent door te geven.

Het laadscript laden.cypher

Dit script bouwt de oefendata op zonder CSV-bestanden. Het eerste blok maakt de unieke sleutels, het tweede de gegevens. Het gebruikt MERGE, dus nog een keer uitvoeren maakt geen dubbelen. Voert de editor maar één statement tegelijk uit, voer dan eerst de zes regels met CREATE CONSTRAINT uit en daarna de rest.

Toon het script (81 regels)
laden.cypher
// Werken met Neo4j: oefendata zonder CSV
// ---------------------------------------
// Bouwt dezelfde graph op als de vier CSV-bestanden in deze map:
// 1 gebouw, 3 verdiepingen, 6 ruimten, 8 elementen, 2 stelsels, 7 klassen
// (27 nodes) en 40 relationships.
//
// Alle codes en namen zijn verzonnen oefendata. Het zijn geen echte
// classificatietabellen.
//
// Gebruik: plak het hele bestand in de querytool en voer het uit. Voert je
// editor maar één statement tegelijk uit, draai dan eerst blok 1 en daarna
// blok 2. Het script gebruikt MERGE: nog een keer draaien maakt geen dubbelen.

// Blok 1: unieke sleutels (constraints)
CREATE CONSTRAINT gebouw_code IF NOT EXISTS FOR (n:Gebouw) REQUIRE n.code IS UNIQUE;
CREATE CONSTRAINT verdieping_code IF NOT EXISTS FOR (n:Verdieping) REQUIRE n.code IS UNIQUE;
CREATE CONSTRAINT ruimte_code IF NOT EXISTS FOR (n:Ruimte) REQUIRE n.code IS UNIQUE;
CREATE CONSTRAINT element_id IF NOT EXISTS FOR (n:Element) REQUIRE n.id IS UNIQUE;
CREATE CONSTRAINT stelsel_code IF NOT EXISTS FOR (n:Stelsel) REQUIRE n.code IS UNIQUE;
CREATE CONSTRAINT klasse_code IF NOT EXISTS FOR (n:Klasse) REQUIRE n.code IS UNIQUE;

// Blok 2: de data
MERGE (g:Gebouw {code: 'KG'})
  SET g.naam = 'Oefenkantoor'
WITH g
UNWIND [
  {code: 'V00', naam: 'Begane grond',      niveau: 0},
  {code: 'V01', naam: 'Eerste verdieping', niveau: 1},
  {code: 'V02', naam: 'Tweede verdieping', niveau: 2}
] AS v
MERGE (vd:Verdieping {code: v.code})
  SET vd.naam = v.naam, vd.niveau = v.niveau
MERGE (g)-[:HEEFT_VERDIEPING]->(vd)
WITH count(*) AS stap1
UNWIND [
  {verdieping: 'V00', code: 'R0.01', naam: 'Entree',            oppervlakte: 38},
  {verdieping: 'V00', code: 'R0.02', naam: 'Technische ruimte', oppervlakte: 24},
  {verdieping: 'V01', code: 'R1.01', naam: 'Kantoortuin',       oppervlakte: 145},
  {verdieping: 'V01', code: 'R1.02', naam: 'Vergaderruimte',    oppervlakte: 32},
  {verdieping: 'V02', code: 'R2.01', naam: 'Kantoortuin',       oppervlakte: 150},
  {verdieping: 'V02', code: 'R2.02', naam: 'Stilteruimte',      oppervlakte: 12}
] AS r
MATCH (vd:Verdieping {code: r.verdieping})
MERGE (ru:Ruimte {code: r.code})
  SET ru.naam = r.naam, ru.oppervlakte = r.oppervlakte
MERGE (vd)-[:HEEFT_RUIMTE]->(ru)
WITH count(*) AS stap2
UNWIND [
  {stelsel: 'EC', stelselNaam: 'Elementcode (oefen)',        code: 'EC-WA', omschrijving: 'Wanden, binnen'},
  {stelsel: 'EC', stelselNaam: 'Elementcode (oefen)',        code: 'EC-DE', omschrijving: 'Deuren, binnen'},
  {stelsel: 'EC', stelselNaam: 'Elementcode (oefen)',        code: 'EC-VW', omschrijving: 'Verwarming: afgifte'},
  {stelsel: 'EC', stelselNaam: 'Elementcode (oefen)',        code: 'EC-LB', omschrijving: 'Luchtbehandeling'},
  {stelsel: 'OI', stelselNaam: 'Onderhoudsindeling (oefen)', code: 'OI-1',  omschrijving: 'Bouwkundig, jaarlijkse inspectie'},
  {stelsel: 'OI', stelselNaam: 'Onderhoudsindeling (oefen)', code: 'OI-2',  omschrijving: 'Installatie, halfjaarlijks onderhoud'},
  {stelsel: 'OI', stelselNaam: 'Onderhoudsindeling (oefen)', code: 'OI-3',  omschrijving: 'Installatie, kwartaalonderhoud'}
] AS k
MERGE (s:Stelsel {code: k.stelsel})
  SET s.naam = k.stelselNaam
MERGE (kl:Klasse {code: k.code})
  SET kl.omschrijving = k.omschrijving
MERGE (kl)-[:HOORT_BIJ]->(s)
WITH count(*) AS stap3
UNWIND [
  {id: 'E01', naam: 'Binnenwand kantoortuin-vergaderruimte', type: 'wand',                  datum: null,         ruimte: 'R1.01', ec: 'EC-WA', oi: 'OI-1'},
  {id: 'E02', naam: 'Deur vergaderruimte',                   type: 'deur',                  datum: null,         ruimte: 'R1.02', ec: 'EC-DE', oi: 'OI-1'},
  {id: 'E03', naam: 'Radiator kantoortuin 1e',               type: 'radiator',              datum: '2019-03-14', ruimte: 'R1.01', ec: 'EC-VW', oi: 'OI-2'},
  {id: 'E04', naam: 'Radiator vergaderruimte',               type: 'radiator',              datum: '2019-03-14', ruimte: 'R1.02', ec: 'EC-VW', oi: 'OI-2'},
  {id: 'E05', naam: 'Radiator kantoortuin 2e',               type: 'radiator',              datum: '2021-09-01', ruimte: 'R2.01', ec: 'EC-VW', oi: 'OI-2'},
  {id: 'E06', naam: 'Luchtbehandelingskast',                 type: 'luchtbehandelingskast', datum: '2019-02-20', ruimte: 'R0.02', ec: 'EC-LB', oi: 'OI-3'},
  {id: 'E07', naam: 'Deur stilteruimte',                     type: 'deur',                  datum: null,         ruimte: 'R2.02', ec: 'EC-DE', oi: 'OI-1'},
  {id: 'E08', naam: 'Binnenwand stilteruimte',               type: 'wand',                  datum: null,         ruimte: 'R2.02', ec: 'EC-WA', oi: 'OI-1'}
] AS e
MATCH (ru:Ruimte {code: e.ruimte})
MATCH (ec:Klasse {code: e.ec})
MATCH (oi:Klasse {code: e.oi})
MERGE (el:Element {id: e.id})
  SET el.naam = e.naam, el.type = e.type, el.installatiedatum = date(e.datum)
MERGE (el)-[:STAAT_IN]->(ru)
MERGE (el)-[:GECLASSIFICEERD_ALS]->(ec)
MERGE (el)-[:GECLASSIFICEERD_ALS]->(oi)
RETURN count(*) AS elementen;

5

Een datastructuur ontwerpen

Een graph ontwerp je niet vanuit de tabellen die je al hebt, maar vanuit de vragen die je wilt kunnen stellen. Schrijf die vragen eerst in gewone taal op.

Van vragen naar nodes, relationships en properties

  1. Schrijf vijf tot tien vragen op. Voor het oefenkantoor bijvoorbeeld: "Welke elementen hebben kwartaalonderhoud, en op welke verdieping staan ze?" en "Welke elementcode en welke onderhoudsklasse heeft deze radiator?"
  2. Onderstreep de zelfstandige naamwoorden. Gebouw, verdieping, ruimte, element, klasse, stelsel. Dat zijn kandidaten voor een label.
  3. Omcirkel de werkwoorden en voorzetsels. "heeft", "staat in", "valt onder", "hoort bij". Dat worden relationships: HEEFT_VERDIEPING, STAAT_IN, GECLASSIFICEERD_ALS, HOORT_BIJ.
  4. Wat overblijft zijn kenmerken. Naam, oppervlakte, installatiedatum. Dat worden properties.
  5. Teken het en loop elke vraag met je vinger langs de pijlen. Lukt dat niet, dan mist er een node of een relationship.

Om te tekenen is arrows.app handig: een gratis tekentool van Neo4j in de browser. Je zet bolletjes en pijlen neer, geeft ze labels en properties, en kunt de tekening als plaatje of als Cypher bewaren.

Property of eigen node?

De meest gestelde ontwerpvraag. Een vuistregel:

het alleen een kenmerk is van dit ene ding (oppervlakte, installatiedatum)meerdere dingen ernaar verwijzen (vier radiatoren delen klasse EC-VW)
je er alleen op filtert of sorteertje erlangs wilt lopen naar andere gegevens

In het voorbeeld is type (wand, deur, radiator) een property van Element. Het had ook een extra label kunnen zijn, zoals :Element:Radiator. Beide werken. Een property is eenvoudiger zolang je er alleen op filtert.

Meerdere lenzen op hetzelfde element

In een spreadsheet moet je kiezen: welke indeling bepaalt de tabbladen, en welke wordt een extra kolom? Komt er een derde indeling bij, dan komt er weer een kolom, en een vierde. In een graph is elke indeling een eigen stelsel met eigen klassen, en het element wijst naar alle klassen die erop van toepassing zijn. Geen van beide is de hoofdindeling.

Cypher
MATCH (e:Element {id: 'E03'})-[:GECLASSIFICEERD_ALS]->(k:Klasse)-[:HOORT_BIJ]->(s:Stelsel)
RETURN s.naam AS stelsel, k.code AS code, k.omschrijving AS omschrijving
stelselcodeomschrijving
Elementcode (oefen)EC-VWVerwarming: afgifte
Onderhoudsindeling (oefen)OI-2Installatie, halfjaarlijks onderhoud

En je kunt van de ene lens naar de andere kijken. Welke elementen met elementcode verwarming zijn er, waar staan ze, en welk onderhoud hebben ze?

Cypher
MATCH (:Klasse {code: 'EC-VW'})<-[:GECLASSIFICEERD_ALS]-(e:Element)-[:GECLASSIFICEERD_ALS]->(k:Klasse)-[:HOORT_BIJ]->(:Stelsel {code: 'OI'})
MATCH (e)-[:STAAT_IN]->(r:Ruimte)<-[:HEEFT_RUIMTE]-(v:Verdieping)
RETURN e.naam AS element, r.naam AS ruimte, v.naam AS verdieping, k.omschrijving AS onderhoud

Je krijgt de drie radiatoren, twee op de eerste en één op de tweede verdieping, alle drie met halfjaarlijks onderhoud. Een derde indeling toevoegen, bijvoorbeeld een indeling naar contract, is een nieuw stelsel met klassen en nieuwe pijlen. Aan de bestaande gegevens verandert niets.

Een unieke sleutel met een constraint

Geef elk label een property die elke node uniek maakt, zoals een code of id. Leg dat vast met een constraint (een regel die de database bewaakt). Neo4j weigert dan een tweede node met dezelfde waarde, en zoeken op die property gaat snel.

Cypher
CREATE CONSTRAINT ruimte_code IF NOT EXISTS
FOR (n:Ruimte) REQUIRE n.code IS UNIQUE

Maak de constraints vóór je data laadt. Bestaan er al dubbelen, dan weigert Neo4j de constraint. Bekijk wat er is met SHOW CONSTRAINTS. In het voorbeeld kregen de klassecodes een voorvoegsel (EC-, OI-), zodat codes uit twee stelsels nooit botsen. Kunnen twee stelsels dezelfde code hebben, neem dan de stelselcode op in de sleutel.

Indexes

Een index is een opzoeklijst die zoeken op een property versnelt. Een constraint maakt er zelf een. Zoek je vaak op een andere property, maak er dan een:

Cypher
CREATE INDEX element_type IF NOT EXISTS
FOR (e:Element) ON (e.type)

Bij een paar duizend nodes merk je het verschil nauwelijks. Bij honderdduizenden wel. SHOW INDEXES toont wat er is.

Veelgemaakte ontwerpfouten

  • Een lijst in één property. klassen: 'EC-VW;OI-2' kun je niet volgen als verband. Maak er relationships naar klasse-nodes van.
  • Een verwijzing als property laten staan. ruimteCode: 'R1.01' op het element is een spreadsheetgewoonte. In de graph wordt het een STAAT_IN-pijl. De kolom uit de CSV gebruik je alleen bij het laden.
  • Vage relationships. HEEFT of RELATED_TO overal zegt niets. Een specifieke naam (STAAT_IN, HOORT_BIJ) maakt queries leesbaar en snel.
  • Een node per waarde. Een node voor elke datum of elk getal maakt de graph druk zonder iets toe te voegen. Datums en maten zijn properties.
  • Geen sleutel. Zonder unieke property en constraint krijg je vroeg of laat dubbele nodes (hoofdstuk 8).
  • Alles in één label. Eén label Ding met een property soort voor alles maakt elke query trager en onleesbaarder dan aparte labels.

Bronnen: Data modeling, Constraints en Indexes (Engels).

Data importeren

De meeste gegevens die je wilt laden, staan in Excel. De weg naar de graph gaat via een CSV-bestand: platte tekst, één regel per rij, met de kolomnamen in de eerste regel.

Van Excel naar CSV

  1. Zet per soort ding één tabblad klaar: verdiepingen, ruimten, klassen, elementen. Eén rij per ding, kolomnamen zonder spaties in de eerste rij.
  2. Kies Bestand > Opslaan als en als bestandstype CSV UTF-8. UTF-8 zorgt dat letters als é en ë goed overkomen.
  3. Excel slaat alleen het actieve tabblad op. Herhaal het per tabblad.
  4. Open het CSV-bestand één keer in Kladblok (Mac: TextEdit) en kijk welk scheidingsteken er staat: een komma of een puntkomma.

Puntkomma in plaats van komma? Met Nederlandse instellingen gebruikt Excel vaak een puntkomma. Dat is geen probleem: zet dan achter de LOAD CSV-regel FIELDTERMINATOR ';', bijvoorbeeld LOAD CSV WITH HEADERS FROM 'file:///ruimten.csv' AS rij FIELDTERMINATOR ';'. De oefenbestanden gebruiken komma's.

Waar het bestand moet staan

LOAD CSV leest bestanden uit de import-map van de instance. Een adres als file:///ruimten.csv betekent: het bestand ruimten.csv in die map.

  1. Kies in Neo4j Desktop bij je instance het menu met drie puntjes, dan Open > Instance folder.
  2. Open daarin de map import.
  3. Kopieer de vier CSV-bestanden uit voorbeelddata naar die map.

Laden met LOAD CSV en MERGE

Wil je de import zelf oefenen, leeg dan eerst de database als je laden.cypher al had gedraaid (hoofdstuk 7). De volgorde is altijd dezelfde: eerst de constraints, dan alle nodes, dan pas de relationships. Een relationship kan alleen tussen nodes die er al zijn. Voer de blokken één voor één uit.

Stap A · constraints
CREATE CONSTRAINT gebouw_code IF NOT EXISTS FOR (n:Gebouw) REQUIRE n.code IS UNIQUE;
CREATE CONSTRAINT verdieping_code IF NOT EXISTS FOR (n:Verdieping) REQUIRE n.code IS UNIQUE;
CREATE CONSTRAINT ruimte_code IF NOT EXISTS FOR (n:Ruimte) REQUIRE n.code IS UNIQUE;
CREATE CONSTRAINT element_id IF NOT EXISTS FOR (n:Element) REQUIRE n.id IS UNIQUE;
CREATE CONSTRAINT stelsel_code IF NOT EXISTS FOR (n:Stelsel) REQUIRE n.code IS UNIQUE;
CREATE CONSTRAINT klasse_code IF NOT EXISTS FOR (n:Klasse) REQUIRE n.code IS UNIQUE;
Stap B · nodes
LOAD CSV WITH HEADERS FROM 'file:///verdiepingen.csv' AS rij
MERGE (g:Gebouw {code: rij.gebouwCode})
  SET g.naam = rij.gebouwNaam
MERGE (v:Verdieping {code: rij.code})
  SET v.naam = rij.naam, v.niveau = toInteger(rij.niveau);

LOAD CSV WITH HEADERS FROM 'file:///ruimten.csv' AS rij
MERGE (r:Ruimte {code: rij.code})
  SET r.naam = rij.naam, r.oppervlakte = toInteger(rij.oppervlakte);

LOAD CSV WITH HEADERS FROM 'file:///klassen.csv' AS rij
MERGE (s:Stelsel {code: rij.stelselCode})
  SET s.naam = rij.stelselNaam
MERGE (k:Klasse {code: rij.code})
  SET k.omschrijving = rij.omschrijving;

LOAD CSV WITH HEADERS FROM 'file:///elementen.csv' AS rij
MERGE (e:Element {id: rij.id})
  SET e.naam = rij.naam, e.type = rij.type,
      e.installatiedatum = date(rij.installatiedatum);
Stap C · relationships
LOAD CSV WITH HEADERS FROM 'file:///verdiepingen.csv' AS rij
MATCH (g:Gebouw {code: rij.gebouwCode})
MATCH (v:Verdieping {code: rij.code})
MERGE (g)-[:HEEFT_VERDIEPING]->(v);

LOAD CSV WITH HEADERS FROM 'file:///ruimten.csv' AS rij
MATCH (v:Verdieping {code: rij.verdiepingCode})
MATCH (r:Ruimte {code: rij.code})
MERGE (v)-[:HEEFT_RUIMTE]->(r);

LOAD CSV WITH HEADERS FROM 'file:///klassen.csv' AS rij
MATCH (k:Klasse {code: rij.code})
MATCH (s:Stelsel {code: rij.stelselCode})
MERGE (k)-[:HOORT_BIJ]->(s);

LOAD CSV WITH HEADERS FROM 'file:///elementen.csv' AS rij
MATCH (e:Element {id: rij.id})
MATCH (r:Ruimte {code: rij.ruimteCode})
MATCH (ec:Klasse {code: rij.elementcode})
MATCH (oi:Klasse {code: rij.onderhoudsklasse})
MERGE (e)-[:STAAT_IN]->(r)
MERGE (e)-[:GECLASSIFICEERD_ALS]->(ec)
MERGE (e)-[:GECLASSIFICEERD_ALS]->(oi);

Zo lees je een blok: LOAD CSV WITH HEADERS leest het bestand regel voor regel en noemt elke regel rij. Met rij.code pak je de waarde uit de kolom code; de kolomnaam moet precies zo geschreven zijn als in de eerste regel van het bestand. Omdat alles met MERGE gaat, mag je een blok gerust nog eens uitvoeren.

Zonder Cypher: de tool Import

Neo4j Desktop heeft ook een importeerhulp met muis en formulier: Import in de zijbalk, onder Tools. Buiten Desktop heet hij Data Importer.

  1. Open Import en kies je instance.
  2. Sleep de CSV-bestanden in het venster, of blader ernaar.
  3. Teken het model: een bolletje per label, een pijl per relationship.
  4. Koppel elk bolletje en elke pijl aan het bestand en de kolommen waar de gegevens in staan, en kies per label de sleutelkolom.
  5. Start de import en controleer daarna met de tellingen hierboven.

Import is prettig voor een eerste keer. LOAD CSV is beter als je dezelfde import vaker wilt herhalen, omdat je de query kunt bewaren. Bronnen: Import in Neo4j Desktop, Data Importer en LOAD CSV (Engels).

Bewaren en opruimen

Een back-up maken: een dump

Een dump is één bestand met de hele inhoud van een database. Daarmee zet je een database later terug, of geef je hem aan een collega.

  1. Stop de instance. Exporteren kan alleen bij een gestopte instance.
  2. Kies in het menu met drie puntjes Export databases.
  3. Vink de database neo4j aan. De database system kan niet mee.
  4. Klik op Export .dump en kies een map. Je krijgt een bevestiging met een snelkoppeling naar de map.

Een dump terugzetten

  1. Stop de instance en kies in het menu met drie puntjes Load database from file.
  2. Kies het .dump-bestand en klik op Import. De database krijgt de naam van het bestand. Die naam mag in de instance nog niet bestaan: terugzetten overschrijft nooit een bestaande database.
  3. De instance start daarna vanzelf. Kies in Query de nieuwe database.

Je kunt ook een nieuwe instance maken vanuit een dump-bestand. Bron: Database management (Engels).

Een database leegmaken

Cypher
MATCH (n)
DETACH DELETE n

Dit verwijdert alle nodes en relationships. Constraints en indexes blijven staan. Voor de oefendata is dat prima. Wil je ook die weg, bekijk ze dan met SHOW CONSTRAINTS en SHOW INDEXES en verwijder ze bij naam:

Cypher
DROP CONSTRAINT ruimte_code

Bij een database met honderdduizenden nodes is één grote verwijderopdracht te zwaar. Verwijder dan in porties: MATCH (n) CALL (n) { DETACH DELETE n } IN TRANSACTIONS OF 1000 ROWS. Meldt de querytool dat dit niet in een gewone transactie kan, zet er dan :auto voor. Bron: CALL subqueries in transactions (Engels).

Opnieuw beginnen

  • Alleen de gegevens opnieuw: maak de database leeg en draai laden.cypher of je import opnieuw.
  • Een tweede database naast de eerste: start de instance, maak met de knop op de kaart een nieuwe database aan en geef hem een naam. Je kiest hem daarna in Query.
  • Helemaal schoon: kies in het menu met drie puntjes Delete. Dat verwijdert de instance met alle databases erin. Maak eerst een dump als je iets wilt bewaren.

Veelgemaakte fouten en wat je dan ziet

Eerste hulp bij een foutmelding: lees de eerste regel van de melding. Die zegt meestal precies wat er mis is, met de plek in de query.

Dubbele nodes door CREATE

Wat je ziet: tellingen die te hoog zijn, of in de graph twee bolletjes met dezelfde naam. Vaak na een import die twee keer is uitgevoerd met CREATE.

Wat je doet: gebruik MERGE op de sleutel en leg een constraint aan (hoofdstuk 5). Dubbelen vind je zo:

Cypher
MATCH (e:Element)
WITH e.id AS id, count(*) AS aantal
WHERE aantal > 1
RETURN id, aantal

Bij een kleine oefendatabase is leegmaken en opnieuw laden het snelst.

Een cartesisch product: veel te veel rijen

Wat je ziet: een resultaat met veel meer rijen dan je verwacht. MATCH (e:Element), (r:Ruimte) RETURN count(*) geeft 48: elke combinatie van 8 elementen en 6 ruimten, of ze nu iets met elkaar te maken hebben of niet. De querytool waarschuwt er vaak voor.

Wat je doet: verbind de twee delen met een relationship: MATCH (e:Element)-[:STAAT_IN]->(r:Ruimte). Twee losse patronen met een komma zijn alleen bedoeld als je echt alle combinaties wilt, of als je beide op een sleutel vastzet (zoals in stap 4 van hoofdstuk 4).

De richting vergeten of omgedraaid

Wat je ziet: geen enkele rij, zonder foutmelding. MATCH (e:Element)<-[:STAAT_IN]-(r:Ruimte) zoekt pijlen van ruimte naar element, en die bestaan niet.

Wat je doet: kijk in het schema (CALL db.schema.visualization()) welke kant de pijl op wijst. Twijfel je, laat de pijlpunt dan weg: -[:STAAT_IN]- vindt het verband in beide richtingen. Bij het aanmaken met CREATE of MERGE is een richting wel verplicht.

Alles ophalen zonder LIMIT

Wat je ziet: een querytool die lang laadt of vastloopt, of een graph die één grijze kluwen is. MATCH (n) RETURN n op een database met honderdduizenden nodes vraagt het onmogelijke van je scherm.

Wat je doet: begin verkennen altijd met LIMIT 25, tel eerst (RETURN count(*)) en vraag daarna gericht op. De instelling voor het maximale aantal nodes in de graphweergave beschermt je deels, maar de query draait wel.

Getallen die als tekst zijn geladen

Wat je ziet: WHERE r.oppervlakte > 100 geeft niets, terwijl er grote ruimten zijn. De oppervlakte is als tekst '145' geladen, en tekst is niet te vergelijken met een getal.

Wat je doet: zet het om bij het laden met toInteger() of toFloat(), of herstel het achteraf: MATCH (r:Ruimte) SET r.oppervlakte = toInteger(r.oppervlakte).

LOAD CSV vindt het bestand niet

Wat je ziet: een melding als Couldn't load the external resource at: file:///ruimten.csv.

Wat je doet: controleer of het bestand in de map import van de draaiende instance staat (menu met drie puntjes, Open > Instance folder), en of de naam precies klopt, ook hoofdletters en de extensie. Windows verbergt extensies soms: ruimten.csv.txt ziet eruit als ruimten.csv.

DELETE wordt geweigerd

Wat je ziet: een melding dat de node niet verwijderd kan worden omdat hij nog relationships heeft.

Wat je doet: gebruik DETACH DELETE als je de verbanden ook kwijt wilt. Bekijk eerst met RETURN wat eraan vastzit.

De database is niet gestart

Wat je ziet: de querytool maakt geen verbinding, of meldt dat de database niet beschikbaar is.

Wat je doet: start de instance in Neo4j Desktop met de startknop op de kaart en verbind daarna opnieuw via Connect > Query. Er kan maar één instance tegelijk draaien; als je er net een andere hebt gestart, is de vorige gestopt.
